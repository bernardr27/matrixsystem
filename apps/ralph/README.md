# Ralph — The Matrix Autonomous Loop Engine

> **"Don't stop until it's done."**

Ralph is the PRD-driven autonomous task engine at the heart of the Matrix development pipeline. Write a PRD once, Ralph feeds tasks one at a time to Claude Code (or Sage for lightweight work), loops until everything passes, then signals `<promise>COMPLETE</promise>`.

## Quick Start

### PRD Mode (Recommended)
```bash
# Process a feature PRD — Ralph loops until all tasks are checked off
node apps/ralph/ralph.mjs --prd docs/prd/MY_FEATURE.md
```

### Freeform Mode
```bash
# Give Ralph a goal and let it figure out the tasks
node apps/ralph/ralph.mjs "Build a dark mode toggle for Nexus"
```

### Interactive Mode
```bash
# Ralph will ask for your objective
node apps/ralph/ralph.mjs
```

## The Pipeline

```
You (Phone) → Ghost Command → Antigravity (Desktop)
    ↓
Gemini/Claude turns your description into PRD.md
    ↓
Ralph reads PRD → finds next unchecked task
    ↓
Feeds task to Claude Code (writes code → runs tests → commits)
    ↓
Loops to next task → until COMPLETE
    ↓
Sage validates environment (deps, ports, builds, logs)
    ↓
Auto-deploy
```

## Architecture

| Component | File | Purpose |
|-----------|------|---------|
| **Ralph CLI** | `apps/ralph/ralph.mjs` | Entry point — PRD mode or freeform mode |
| **Ralph Core** | `core/sage/ralph-core.mjs` | PRD parser, task loop, Think→Act→Observe engine |
| **Sage Engine** | `core/sage/engine.mjs` | LLM client (Ollama) + `SageEnvironment` checks |
| **Sage Check** | `core/sage/check.mjs` | Standalone environment health scan |

## PRD Protocol

1. Before coding anything, create `docs/prd/FEATURE_NAME.md` using the template at `docs/templates/PRD_TEMPLATE.md`.
2. Each task in the PRD must fit in one context window. Split if too large.
3. After each task: write code → run tests → commit → update `progress.md` → mark checkbox.
4. Output `<promise>COMPLETE</promise>` only when ALL checklist items pass.
5. On failure: document what failed in progress file, retry with fix. Escalate after 3 failures.

## Sage Protocol

Before any structural change, Sage validates:
- Dependencies installed (`node_modules` exists)
- Environment variables set
- Ports available (3000, 3001, 4000, 5173)
- Builds clean (`.next` directory exists)
- No broken imports in logs

Run standalone: `node core/sage/check.mjs`

## Tools

Ralph has access to:
1. `LIST_DIR(path)` — List files in a directory
2. `READ_FILE(path)` — Read file content
3. `WRITE_FILE(path, content)` — Create or overwrite a file
4. `EXECUTE(command)` — Run a shell command
5. `SEARCH_FILES(term, dir)` — Recursive text search
6. `MEMORY(text)` — Store an observation
7. `COMPLETE(result)` — Signal task completion

## Configuration

Ralph uses the **Sage Engine** to communicate with the local LLM (Ollama).

| Env Variable | Default | Description |
|-------------|---------|-------------|
| `AI_BASE_URL` | `http://localhost:11434/v1` | Ollama API endpoint |
| `AI_API_KEY` | `ollama` | API key |
| `AI_MODEL` | `llama3.2:latest` | Model name |
| `MATRIX_ROOT` | `g:\matrix` | Matrix workspace root |

## API Integration

- **Nexus**: `GET /api/pipeline` — Pipeline & environment status
- **RocketCommand**: `GET /api/sage-check` — Full Sage environment report with latency metrics
